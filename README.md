# Ara

macOS 15 이상 / Apple Silicon ARM64용 로컬 영상 편집 MVP. Swift 6, SwiftUI·AppKit, AVFoundation, Core Image와 Metal 장치를 사용하는 CIContext로 구현했다. 외부 Swift 패키지, 웹뷰, 서버 처리 없이 가져오기 → 타임라인 편집 → 미리보기 → 프로젝트 저장 → MP4 출력이 연결된다.

## 빌드·실행

Xcode 16 이상과 Swift 6 툴체인이 필요하다. 검증 환경은 Xcode 27 / Swift 6.4 / macOS 27 / ARM64다.

```sh
./scripts/build-app.sh
open "build/Ara.app"
```

기본 빌드는 ARM64 Release다. Debug는 `./scripts/build-app.sh debug`. Xcode에서 `Package.swift`를 열어 `Ara` executable을 실행해도 된다. Xcode 설치 경로가 다르면 `DEVELOPER_DIR`를 지정한다. 전역 `xcode-select` 설정은 변경하지 않는다.

앱 이름은 Ara, 고정 강조색은 연푸른색 `#9ACBFF`다. SwiftUI 컨트롤과 AppKit 타임라인의 선택·재생 헤드·드롭 표시·오디오 파형에 같은 색상을 사용한다. 기존 문서와 미디어 북마크 호환성을 위해 내부 앱 식별자와 `.framestudio` 확장자는 유지한다.

앱은 개발용 ad-hoc 서명이다. 배포용 Developer ID 서명·공증·App Store 샌드박스 패키징은 포함하지 않는다. 앱을 종료한 뒤 같은 경로에 다시 빌드한다.

## 사용 순서

1. 새 프로젝트에서 프레임률을 고른다. 클립 추가 후에는 프레임률이 잠긴다.
2. **Import / ⌘I**로 영상·오디오·PNG/JPEG/8-bit TIFF를 가져온다. Finder 파일을 라이브러리 또는 타임라인에 드롭해 가져올 수도 있다.
3. 라이브러리 **썸네일을 원하는 트랙·시간에 드래그**한다. 더블클릭 또는 `+`는 V1/A1 끝에 추가하며 우클릭 메뉴로 대상 레인을 고를 수 있다. 영상의 원본 오디오는 연결된 A1/A2 클립이 된다.
4. 클립 중앙을 드래그해 이동하고 양끝 손잡이로 트림한다. 눈금자를 클릭·드래그해 스크럽한다. 선택 클립은 **⌘B**로 재생 헤드에서 분할한다.
5. 인스펙터에서 변형·색상·볼륨을 조절한다. **Text / ⇧⌘T**는 V2의 재생 헤드 위치에 3초 텍스트를 추가한다. 점유된 구간에서는 오류를 표시한다.
6. **⌘S**로 `.framestudio` 프로젝트를 저장한다. 원본 파일은 프로젝트에 복사되지 않는다. 원본이 없으면 라이브러리의 **Relink**로 연결한다.
7. **Export / ⌘E**에서 1080p 또는 4K를 선택하고 MP4를 저장한다. 출력은 H.264 + AAC 스테레오, SDR Rec.709, 현재 프로젝트 프레임률이다.
8. 타임라인 툴바의 **카메라 / ⇧⌘E**는 현재 프레임을 **1920×1080 sRGB PNG**로 저장한다. 미리보기와 같은 컷·합성·텍스트·효과를 반영하며, 앱 창의 크기와 관계없이 캔버스 전체를 캡처한다. 재생 중에는 일시정지하고 저장 위치를 선택한다. 프로젝트 끝에서는 마지막 유효 프레임을 사용한다. 이전 색공간 수정 전 버전의 PNG는 원본 영상에서 다시 캡처해야 한다.
9. 미리보기 재생 컨트롤의 양끝 버튼 또는 **⌥← / ⌥→**로 선택 클립의 처음·마지막 프레임으로 이동한다. 끝 시간은 다음 클립의 첫 프레임이 아니라 선택 클립 안의 마지막 프레임이다. 화면 밖으로 이동하면 타임라인도 따라 스크롤한다.
10. 미리보기의 영상·이미지·텍스트를 **더블클릭**하면 파란 테두리와 네 모서리 조절점이 나타난다. 안쪽을 드래그하면 이동하고 모서리를 드래그하면 반대 모서리를 기준으로 비율을 유지하며 크기가 바뀐다. 핀치 또는 **⌥+스크롤**은 중심을 기준으로 확대·축소한다. 변경은 인스펙터와 저장·출력에 반영되며 한 번의 드래그는 한 번의 Undo로 복원된다. **Esc**는 변형 모드를 닫고, 드래그 중 누르면 해당 드래그를 취소한다.

| 조작 | 동작 |
|---|---|
| Space | 재생 / 일시정지 |
| ← / → | 이전 / 다음 프레임 |
| ⌥← / ⌥→ | 선택 클립의 처음 / 마지막 프레임 |
| ⇧⌘E | 현재 합성 프레임을 PNG 스냅샷으로 저장 |
| Shift + ← / → | 타임라인에 포커스가 있을 때 10프레임 이동 |
| ⌘B | 선택 클립 및 연결 오디오 분할 |
| ⌘C / ⌘V | 타임라인 선택 클립 복사 / 재생 헤드 위치에 붙여넣기 |
| Delete | 선택 클립 및 연결 오디오 삭제 |
| ⌘Z / ⇧⌘Z | Undo / Redo |
| N | 경계·재생 헤드 스냅 켜기/끄기 |
| Shift + 드래그 | 해당 드래그의 스냅 해제 |
| 핀치 / Zoom 슬라이더 | 타임라인 확대·축소 |
| 가로 스크롤바 / 트랙패드 | 타임라인 수평 이동 |
| ⇧⌘S | 다른 이름으로 저장 |

타임라인을 클릭한 뒤 **⌘C**로 선택 클립과 연결 오디오를 복사한다. **⌘V**는 복사한 트랙의 재생 헤드 위치에 트림·효과·볼륨을 유지한 새 클립을 만든다. 같은 트랙의 기존 클립과 겹치면 붙여넣기를 취소하고 안내한다. 프로젝트 간 복사는 프레임률이 같아야 하며, 인스펙터의 텍스트 입력칸에서는 일반 텍스트 복사·붙여넣기가 작동한다.

## 구현 범위

- 리사이즈 가능한 라이브러리·프로그램 모니터·인스펙터·타임라인, 어두운 네이티브 UI.
- 영상 2개·오디오 2개 레인, **V2가 V1 위**에 합성. 같은 레인 내 겹침은 거부한다.
- 선택, 연결 이동·시작/끝 트림·분할·삭제, 스냅, 프레임 이동, NDF 타임코드, Undo/Redo 100단계.
- 위치, 크기, 회전, 불투명도, 밝기·대비·채도, 볼륨·음소거, 한글 포함 텍스트·폰트 크기·색상.
- 비동기 메타데이터·썸네일·파형 분석, 디스크 캐시, 구간 중심 타임라인 그리기, 오래된 재생 구성·seek 취소/무시.
- 버전 1 JSON 편집 문서, 원본 구간/배치 구간 분리, 원자적 저장, 보안 범위 북마크, 누락 미디어 재연결.
- 미리보기·출력이 같은 합성기/효과/오디오 믹스를 사용한다. 빈 구간, 정지 이미지·텍스트만 있는 프로젝트, 오디오 전용 프로젝트도 출력한다.
- HDR 소스는 디코더가 준비되기까지 세그먼트마다 약 3프레임을 내주지 않는다. 그 구간은 클립의 첫 프레임으로 메워 검은 깜빡임이나 렌더 중단이 생기지 않게 한다.
- 진행률·취소·오류 처리. 성공 전 목적지 파일을 교체하지 않으며 임시 작업 폴더를 정리한다. 원본과 같은 경로로 내보내는 작업은 차단한다.

## 구조

| 경로 | 역할 |
|---|---|
| `Sources/FrameCore` | UI·AVFoundation과 분리된 Codable 모델, 정수 틱 시간, 편집 연산, 검증, Undo/Redo |
| `Sources/FrameMedia` | 가져오기·북마크·캐시, AVComposition 생성, Core Image 커스텀 합성, MP4 reader/writer |
| `Sources/FrameStudio` | SwiftUI 패널, AppKit 타임라인/드래그/플레이어, 비동기 상태 관리 |
| `Sources/FrameProbe` | 실제 미디어를 쓰는 통합 검증 실행기 |
| `Tests/FrameCoreTests` | 시간·연결 편집·원자성·저장 복원·잘못된 문서 검증 |

시간은 초당 600,000 정수 틱으로 표현한다. 24/25/30/50/60 및 24000/1001·30000/1001·60000/1001 프레임이 정확한 정수 틱이다. 재생·출력 시에만 CMTime/AVComposition으로 변환하고 MP4 트랙·무비 시간 단위도 같은 정밀도를 사용한다. `@unchecked Sendable`은 생성 후 불변으로 공유하는 AVFoundation/CI 객체와 잠금·직렬 큐로 보호되는 합성기 경계에 한정했다.

## 검증 실행

단위 테스트에는 외부 도구가 필요 없다.

```sh
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer swift test --arch arm64
```

통합 검증에는 테스트 픽스처 생성·독립 분석용 `ffmpeg`, `ffprobe`, Python 3가 필요하다. 이들은 앱에 포함되거나 앱에서 호출되지 않는다.

```sh
./scripts/validate.sh
```

스냅샷만 검증하려면 기존 픽스처를 사용해 다음 명령을 실행한다. 영상 겹침·효과·텍스트·이미지·빈 구간·마지막 프레임의 PNG를 MP4 출력과 비교하고 색상 프로필, 취소와 실패 시 기존 파일 보존을 확인한다.

```sh
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer swift run --arch arm64 FrameProbe snapshot TestArtifacts/fixtures TestArtifacts/snapshot-validation
```

[스냅샷·클립 이동 검증 기록](docs/validation/snapshot-navigation.md)에 실제 실행 결과와 확인하지 못한 항목을 정리했다.

PNG 재가져오기 색상 회귀 검증은 `FrameProbe snapshot-roundtrip --chart TestArtifacts/snapshot-color-chart`로 실행한다. `--chart` 대신 영상/이미지 경로도 사용할 수 있다. 중간톤 차트를 캡처·재가져오기 3회 반복하고 MP4 출력까지 비교한다. [색공간 수정 기록](docs/validation/snapshot-color.md)을 참고한다.

결과는 `TestArtifacts/results/`에 생성된다. `Validation.framestudio`에는 검증 타임라인이 저장된다. FrameProbe가 만든 보안 북마크는 앱의 접근 권한과 다르므로, 앱에서 처음 열 때 라이브러리의 Relink로 해당 픽스처를 선택해야 한다. 이번 GUI 검증에서 앱으로 저장한 `TestArtifacts/fixtures/GUI-Automation.framestudio`도 제공한다. [실제 검증 기록](docs/validation/RESULTS.md)과 [오픈소스·Apple 자료 검토](docs/research/implementation-review.md)를 참고한다.

## 현재 제한

- 고정 16:9 캔버스, 4개 레인, 한 번에 한 프로젝트/클립 선택. 같은 레인 덮어쓰기·리플 편집·트랜지션·키프레임·속도 변경·오디오 분리/재연결 UI는 없다.
- 출력은 SDR Rec.709만 지원한다. HDR 영상(PQ·HLG, BT.2020, 10-bit)은 **가져올 수 있으며 SDR Rec.709로 톤매핑**해 편집·출력한다. HDR을 HDR로 유지하는 출력은 범위 밖이다. 표시된 log와 Dolby Vision(dvh1/dvhe), 고비트 심도 및 HDR 게인맵 **이미지** 입력은 여전히 오류로 거부한다. HEIC/RAW는 지원하지 않는다. 색 정보가 잘못되거나 없는 파일의 원래 촬영 모드는 자동 판별할 수 없다.
- AVFoundation이 읽을 수 있는 미디어의 첫 영상/오디오 스트림을 사용한다. DRM 파일은 지원하지 않는다. 모든 카메라·코덱 조합을 시험한 것은 아니다.
- 표시는 NDF다. 드롭 프레임 타임코드·OTIO/FCPXML 교환·프록시·고급 HDR·멀티캠·플러그인·AI는 범위 밖이다.
- 썸네일은 원본당 대표 이미지, 파형은 최대 16,000 peak다. 긴 영상의 모든 프레임을 메모리에 올리지 않지만 수 시간 프로젝트·수천 클립의 성능은 실측하지 않았다. 미디어 캐시 자동 용량 제한과 크래시 후 자동 복구는 없다.
- 저장은 수동이다. 앱 재실행 후 접근은 북마크로 복원하지만, 이동식 디스크 권한 변화·다른 Mac으로 문서 이동 시 재연결이 필요할 수 있다.
- macOS 15 최소 타깃 빌드는 확인했다. macOS 15 실제 장비, Intel, 배포 서명/공증, 앱 샌드박스에서는 검증하지 않았다.
